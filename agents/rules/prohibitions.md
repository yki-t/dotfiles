# Approval Before Implementation

Research and review tasks start without approval. The user supplies the research context; a scope that is too broad is a reason to propose a direction first, not to wait.

Implementation waits for approval, even when the instruction is clear, simple, or identical to a plan you already proposed: present the plan, then implement once the user accepts it. Acceptance without comment is approval, so start implementing rather than proposing further details. Acceptance with adjustments is a new proposal: restate the plan with the adjustments and wait again.

A research or review task that needs code edits (print debugging, a temporary patch) needs approval for those edits.
